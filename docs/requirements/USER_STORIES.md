| Épica                     | Agrupa historias por dominio funcional.                                                                                                               |
| Módulo                    | Subárea del sistema.                                                                                                                                  |
| Rol                       | Actor principal que obtiene valor de la historia.                                                                                                     |
| Historia de usuario       | Redacción en formato: Como [rol] quiero [función] para [beneficio].                                                                                   |
| Criterios de aceptación   | Condiciones observables que deben cumplirse para dar la historia por aceptada.                                                                        |
| Prioridad                 | MoSCoW: Must = indispensable para MVP; Should = importante; Could = deseable.                                                                         |
| SP                        | Story Points sugeridos (1,2,3,5,8) para estimación relativa; el equipo puede reestimarlos.                                                            |
| Dependencias              | Historias o componentes requeridos antes o durante su desarrollo.                                                                                     |
| Entidades BD              | Tablas/relaciones principales esperadas; es una guía, no sustituye el modelo ER.                                                                      |
| Trabajo Web               | Interfaces o componentes web que probablemente se desarrollarán.                                                                                      |
| Ing. de Software          | Artefactos/reglas/pruebas que deben documentarse.                                                                                                     |
| Release                   | MVP, Versión 1 o Versión 2.                                                                                                                           |
| Sprint sugerido           | Orden didáctico propuesto; puede ajustarse a la duración real del curso.                                                                              |
| Estado                    | Pendiente / En análisis / En desarrollo / En pruebas / Terminado / Bloqueado.                                                                         |
| Definition of Ready (DoR) | La historia tiene rol, objetivo, criterios claros, dependencias conocidas y datos/maquetas suficientes para comenzar.                                 |
| Definition of Done (DoD)  | Código integrado; BD/migración aplicada; validaciones y permisos implementados; criterios probados; documentación actualizada; sin defectos críticos. |
